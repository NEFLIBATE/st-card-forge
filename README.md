# ✦ 角色卡工坊 · Card Forge

一个中文 SillyTavern 第三方 UI 扩展：写下一段灵感，用酒馆当前连接的模型生成角色卡，逐字段编辑后直接添加到角色列表，或导出可分享的 JSON / PNG 角色卡。

版本：**1.1.0** · 许可证：MIT · 无生产依赖 · 无需编译或额外后端

## 1.1.0：更多人物细节

在「01 创作」新增 **6 组、35 项可选细节**，按需展开即可填写。已填写项目会参与整卡生成和字段重写，并自动保存；旧版文字草稿继续保留。

| 分组 | 可填写的内容 |
| --- | --- |
| 身份与生活 | 可选性别、年龄、物种、职业、出身、生活与社会地位 |
| 外貌与感官 | 外貌、服饰与物品、动作与感官印象、声线 |
| 经历与世界 | 成长经历、人生转折、目标、秘密、世界规则 |
| 性格与内心 | 性格、缺点、内在矛盾、原则、恐惧、喜好、厌恶 |
| 关系与成长 | 初始态度、信任条件、冲突与修复、关系节奏、其他人物 |
| 对白与互动 | 语言风格、代表台词、习惯、能力与代价、开场、剧情钩子、内容边界 |

- **深度模式**：要求交代经历与行为的联系、目标冲突、秘密揭露条件、关系变化及可持续互动线索。
- **数量可选**：备选开场白 0–5 条，对话示例 1–6 组，启用世界书时选择 3／5／8／10 条。选择 0 条备选开场白仍保留主开场。
- **性别可留空**：默认不指定；可以自行选择。其他细节也不要求全部填满。
- **细节管理**：分组显示填写数量，支持展开全部、收起全部、清空细节。清空细节保留已生成的角色卡和核心设定。
- 细节会融入 V2 标准字段：身份经历进入描述，动机矛盾进入性格，关系与剧情进入场景，开场与对白分别进入相应字段。
- 数量与内容要求通过提示传给模型；模型可能少写、偏离或截断，请在导入前检查。细节多时建议 8192 tokens，并按模型实际上限调整。

**升级方法：**在酒馆「扩展 → 管理扩展」中更新本扩展并刷新页面，标题应显示 `1.1.0`。安装地址保持不变。

## 功能

- **完整生成**：名称、描述、性格、场景与玩家关系、首条开场白、对话示例、标签、可选数量的备选开场白。
- **逐字段重写**：只重新生成指定字段，其余设定保留；替换已有内容前在界面内确认。
- **玩家人设参考**：不引用、引用当前人设，或选择酒馆中已保存的人设。不会切换酒馆的当前人设。
- **创作选项**：题材、语言、叙述风格、篇幅、额外要求、输出 tokens 上限。
- **可选世界书**：生成 3／5／8／10 条内嵌世界书，可在 JSON 编辑器修改关键词和条目。
- **头像**：本地上传 PNG、JPG 或 WebP，最长边缩放至 1600 像素以内；无头像时生成文字封面。此扩展不生成 AI 图片。
- **V2 JSON / PNG 导出**：PNG 内嵌 `chara` 元数据，保留 Unicode、占位符及第三方扩展字段。
- **载入旧卡**：支持 V1 / V2 JSON 和包含 V2 `chara` 数据的 PNG，载入前确认。
- **直接导入酒馆**：通过酒馆自己的角色导入接口添加一个新角色，同名时交给酒馆分配文件名；不传入覆盖参数。
- **草稿**：自动保存一份文字草稿和创作设定到酒馆扩展设置；头像和原始模型输出仅在当前页面会话保留。
- **手机布局**：窄屏单列、内部滚动、固定导出区；支持键盘导航和 Escape 关闭。
- **错误恢复**：保留模型原始输出，允许手动修正 JSON 后解析；生成失败不替换原角色卡。

## 通过 GitHub 安装

在酒馆的 **扩展 → 安装扩展** 中粘贴以下仓库地址：

```text
https://github.com/NEFLIBATE/st-card-forge
```

安装后刷新页面，在扩展设置中找到 **角色卡工坊 → 打开角色卡工坊**。

以下上传步骤供下载源码后二次发布使用；直接安装本仓库时可跳过。

### 第一步：上传 GitHub

1. 在 GitHub 新建仓库，建议命名为 `st-card-forge`。如需普通仓库链接安装，使用公开仓库最方便。
2. 解压源码包，将**解压得到的文件和目录**上传到仓库根目录。不要直接上传 ZIP，也不要再套一层 `st-card-forge` 文件夹。
3. 检查仓库首页能直接看到 `manifest.json`、`index.js`、`core.js`、`png.js`、`style.css` 和 `README.md`。
4. 提交文件，复制你自己的仓库主页地址。格式示例：`https://github.com/你的用户名/st-card-forge`。本项目已发布的安装地址是 `https://github.com/NEFLIBATE/st-card-forge`。

运行时必须有以下文件位于仓库根目录；其余测试和文档文件建议一并保留：

| 文件 | 用途 |
| --- | --- |
| `manifest.json` | 酒馆读取的扩展清单 |
| `index.js` | 界面、生成与角色导入 |
| `core.js` | 角色卡格式、校验与提示构建 |
| `png.js` | PNG 角色卡读写 |
| `style.css` | 电脑与手机样式 |

### 第二步：在酒馆安装

1. 打开 SillyTavern → **扩展** → **安装扩展**。
2. 粘贴你刚上传的 **GitHub 仓库地址**，不要粘贴 ZIP、单个文件或网页预览地址。
3. 安装完成后刷新酒馆页面。
4. 在扩展设置中找到 **角色卡工坊** → **打开角色卡工坊**。如酒馆提供聊天扩展菜单，也可从那里打开。

安装目录由酒馆管理。手动安装时，可将五个运行文件放在 `SillyTavern/public/scripts/extensions/third-party/st-card-forge/`，然后刷新；通常需要服务器文件访问权限。

## 使用

1. 先在酒馆配置并连接文本生成 API。
2. 打开工坊，在 **01 创作** 写核心设定，选择题材、风格，以及是否引用玩家人设或生成世界书。
3. 点击 **生成角色卡**，等待完成。请求使用当前 API 和采样设置，消耗对应 API 额度。
4. 在 **02 角色卡** 修改字段、上传头像；想改某一部分时用该字段旁的 **重写**。
5. 在 **03 预览** 检查内容；预览按纯文本展示，不执行卡片中的 HTML 或脚本，也不模拟实际聊天效果。
6. 点击 **导入酒馆** 并确认，即添加一个新角色；或导出 JSON / PNG，通过酒馆的角色导入功能载入。

**示例核心设定：**

> 一个经营午夜书店的失忆魔女。她能从旧书中读出失落的记忆，但每次使用能力，都会忘记自己的一个小习惯。玩家带着一张被雨浸坏的地图前来求助。风格温柔、神秘，保留长期互动空间。

## 模型、预设与数据范围

- 使用 `SillyTavern.getContext().generateRaw({...})`，不存储或读取你的 API 密钥，也不直接连接外部模型地址。
- 沿用酒馆当前连接和采样设置；界面显示当前预设名称供参考。**预设的系统提示、提示管理器内容、当前聊天和当前角色卡不会由本扩展主动拼入制卡请求**。其他扩展可以通过酒馆事件修改原始生成请求。
- 选择人设后，该人设的名称和描述会作为玩家参考发送给当前模型提供商；不选择则不附带。本扩展不读取人设绑定的世界书。
- 逐字段重写时，会将当前草稿的角色设定作为一致性参考发送给模型。
- 制卡提示中的完整 `{{...}}` 宏会先转成临时文字标记，避免酒馆将它们展开为当前角色名、变量等；解析模型输出时再还原。模型本身仍可能未按提示保留占位符，请在导入前检查。
- 没有统计服务、遥测、外部字体、图片服务或 CDN 依赖。
- 直接导入只请求当前酒馆的 `/api/characters/import`。使用酒馆提供的请求头，并由浏览器设置 multipart 边界。
- 文本草稿通过酒馆自己的扩展设置保存。若多人共用同一酒馆账号，则遵循该账号的设置隔离范围。

## 兼容范围与限制

- 目标是提供 `getContext`、对象参数版 `generateRaw`、`extensionSettings` 和 `saveSettingsDebounced` 的现代 SillyTavern。扩展清单以 1.12.0 为最低加载门槛，**不代表每个历史小版本均已实测**。推荐使用维护中的稳定版；缺少必要接口时会显示错误。
- 支持酒馆 `openai`（Chat Completion）、`textgenerationwebui`、`kobold`、`koboldhorde`、`novel` 主 API 标识；实际生成质量和输出长度由提供商、模型及你的连接决定，未逐个连接实测。
- 不自动要求提供商启用结构化输出，避免不支持 JSON Schema 的服务直接失败。收到模型文本后进行 JSON 解析和字段校验。
- 目前导入编辑器只支持 V1 / V2，**不支持 V3 / CHARX**；PNG 读取支持未压缩 `tEXt/chara` 数据。世界书以 JSON 编辑，尚未提供图形化条目编辑器。
- 名称、描述、首条开场白为导出 / 导入的必填项。保存空白草稿不受限制。
- **放弃本次结果**只忽略返回结果，不会调用酒馆的全局停止接口，也不保证中断计费；等待当前请求结束后可重新生成。关闭窗口不会丢弃正在进行的结果。
- 自动保存一份文字草稿。**刷新页面后需要重新上传头像**；需要带头像保存时请先导出 PNG。原始模型输出不会长期保存。
- 本次会话会防止对相同卡片重复点击导入；刷新页面后该防重复记录不保留。导入响应不确定时，先在酒馆角色列表检查再重试。
- 插件未接入你的酒馆实例。已按官方 `release` 分支接口核对，并使用浏览器模拟宿主验证主要流程；真实 API 连接与具体酒馆版本仍需安装后验证。

## 常见问题

**找不到扩展 / 插件不加载**

检查仓库根目录是否有 `manifest.json` 和对应 JS / CSS 文件；确认扩展已启用，然后硬刷新酒馆。旧版缓存可通过更新扩展后重启酒馆并刷新处理。

**生成后显示 JSON 错误**

增加最大输出 tokens，减少额外要求，或关闭世界书后重试。也可在「01 创作 → 原始输出 / 格式修复」中手动修正为完整 JSON，再点击「解析为完整角色卡」。插件不会自动发起额外付费修复请求。

**导入失败 / 导入成功但列表未更新**

先检查角色列表。若提示列表刷新失败，角色文件已经创建，刷新页面即可。若服务器拒绝导入，可导出 PNG / JSON 后通过酒馆角色面板手动导入。

**手机端导出后在哪里找文件**

查看手机浏览器的下载列表。具体保存位置取决于浏览器和系统权限；若内嵌浏览器拦截下载，使用正常浏览器打开酒馆再试。

## 开发与检查

扩展运行无需 `npm install`。Node.js 22 或更新版本可运行：

```sh
npm run check
npm test
```

浏览器集成检查使用 Python + Playwright + Pillow，模拟酒馆宿主，不调用真实模型：

```sh
pip install playwright pillow
playwright install chromium
python tests/browser_smoke.py
```

可使用环境变量 `CARD_FORGE_CHROMIUM` 指定已安装的 Chromium 可执行文件。脚本输出截图到源码目录旁的 `qa/`，用于本地检查，未包含用户数据。GitHub Actions 默认运行 JS 语法检查和核心测试。
